# 会话终端与断线恢复

每个聊天 Session 的终端单独保存，归属键为服务器 ID 和聊天 Session ID。同目录下的两个聊天不会共享终端；聊天的工作目录改变时，已有终端继续使用创建时的目录。底部、右侧面板和新建终端快捷键使用同一控制器。

打开已有聊天的终端会连接原来的远端 PTY，不会重新创建 shell。切换聊天、隐藏面板、APP 进入后台或客户端断开，仅断开客户端连接；点击终端标签的关闭按钮才会删除远端 PTY。删除失败会保留标签并显示错误。

输出由 xterm 完成处理后，每秒最多保存一次终端画面、滚动位置、尺寸和输出偏移。页面隐藏或正常卸载时立即保存；系统直接杀进程时，通过上次快照的偏移请求远端补回后续输出。偏移按服务端普通 PTY 协议使用 JavaScript UTF-16 字符长度，不能替换为 UTF-8 字节数。

## 恢复边界

- 远端 OpenCode 服务、PTY 和 shell 必须仍然存在。远端服务重启或主动关闭 shell 后，不会自动重跑原来的命令；界面会显示“远端终端已结束或不存在”并保留本地已保存历史。
- 普通长任务完成后，交互 shell 通常仍然运行，能够再次接入并查看结果。任务运行期间关闭客户端不等于关闭远端 shell。
- 本地画面沿用 xterm 的 10,000 行回滚范围。远端回放也有上限；OpenCode v2.0.26 对普通 PTY 保留约 2 Mi UTF-16 字符的输出。离线输出超过远端缓存时，界面明确提示部分较早内容无法恢复。这不是完整、永久的任务日志归档。
- APP 数据被清除、卸载后重装或更换设备，会丢失本地聊天与 PTY 的对应关系。未归属聊天的远端终端可以从对应服务器的工作区页发现。
- 旧版按目录保存的终端记录保留为遗留历史，只在工作区页找到相同远端 PTY ID 后恢复，不猜测其聊天归属。设置备份导入兼容旧格式。
- 本地存储写入失败会在终端中显示错误，不会报告快照保存成功。

实现使用已有的普通 PTY 接口，不要求远端额外安装 `opencode-pty`。服务端连接断开只移除订阅者、输出缓存与偏移定义可见[官方 PTY 实现](https://github.com/anomalyco/opencode/blob/dev/packages/core/src/pty.ts)。

## 验证

自动化覆盖服务器与聊天隔离、同 PTY ID 的旧回调、创建和恢复响应乱序、远端终端消失、关闭失败、快照写入失败，以及 xterm 输出与偏移一致性。

真实 OpenCode v2.0.26 的端到端测试通过新建终端快捷键启动 PowerShell 长任务，输出中文和 emoji；强制结束 Chromium 客户端进程树，不执行正常卸载清理。远端任务继续完成，重新打开相同客户端数据后接入相同 PTY ID 和进程 PID，补回离线输出和完成结果。两个聊天共用同一目录时，分别拥有独立终端；远端总共两个 PTY，恢复没有创建额外 PTY。
